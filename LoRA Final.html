01 · Foundations

What are we actually trying to change?

A pretrained language model already knows language, facts, patterns, and reasoning behaviors. Fine-tuning usually does not need to rebuild that knowledge. It needs to steer the model toward a new behavior, domain, style, or task.

Inside a transformer, most useful computation is matrix multiplication. If a layer receives a vector or a batch of vectors \(X\), a learned weight matrix \(W\) transforms it:

The ordinary linear layer\[Y = XW^\top + b\]

During full fine-tuning, every chosen weight is allowed to move. If the optimized matrix was \(W_0\) before training and becomes \(W'\) afterward, then the learned change is:

Weight update\[W' = W_0 + \Delta W\]

Plain-English picture

Think of \(W_0\) as a gigantic, already-written book. Full fine-tuning rewrites words across the whole book. LoRA freezes the book and attaches a thin correction booklet that says, “When you see this kind of input, adjust the response in this direction.”

Why full fine-tuning becomes expensive

Training memory is not only the model's weights. For each trainable parameter we may also keep a gradient and optimizer states. With Adam-like optimization, two moment estimates are commonly maintained. A rough mixed-precision budget can therefore include FP16/BF16 weights, FP16 gradients, and FP32 optimizer states.

A useful rough model\[M_{train} \approx M_{weights}+M_{gradients}+M_{optimizer}+M_{activations}\]

For \(N\) fully trainable parameters, a rough parameter-state estimate is often around \(16N\) bytes before activations and temporary buffers, depending on the exact optimizer and framework. For billions of parameters, that is the real wall LoRA attacks.

Important nuance

There is no universal “bytes per parameter” constant. Precision, optimizer, gradient checkpointing, sharding, offloading, sequence length, and batch size all change the final number. Use estimates to reason, then measure the actual run.

02 · LoRA intuition

The low-rank hypothesis

LoRA makes a bold but practical assumption: although a model has enormous weight matrices, the useful change needed for a new task may live in a much smaller number of directions.

Instead of directly training every element of the dense update \(\Delta W\in\mathbb{R}^{d_{out}\times d_{in}}\), LoRA writes the update as the product of two thin matrices:

Low-rank factorization\[\Delta W = BA,\qquad A\in\mathbb{R}^{r\times d_{in}},\quad B\in\mathbb{R}^{d_{out}\times r}\]\[r \ll \min(d_{in},d_{out})\]
≈
×

The rank of \(BA\) cannot exceed \(r\). So LoRA constrains the update to a low-dimensional subspace. It does not claim that the original matrix \(W_0\) is low rank. The claim concerns the task-specific update.

Parameter savings, exactly

A dense update has \(d_{out}d_{in}\) trainable values. LoRA has only \(r d_{in}+d_{out}r\):

Trainable parameter count\[P_{full}=d_{out}d_{in}\]\[P_{LoRA}=r(d_{in}+d_{out})\]\[\text{fraction trained}=\frac{r(d_{in}+d_{out})}{d_{out}d_{in}}\]

If \(d_{in}=d_{out}=4096\) and \(r=16\), full training updates \(16{,}777{,}216\) values in that matrix. LoRA updates \(131{,}072\), which is about \(0.78125\%\) as many.

Full update

\(4096\times4096=16.78\) million trainable elements.

Rank-16 LoRA

\(16(4096+4096)=131{,}072\) trainable elements.

Why rank means “number of independent directions”

Matrix \(A\) first projects the input from \(d_{in}\) dimensions down to an \(r\)-dimensional bottleneck. Matrix \(B\) expands those \(r\) coordinates back to \(d_{out}\). The adapter can therefore learn at most \(r\) independent latent adjustment directions.

Input \(x\)\(d_{in}\) features
→
\(Ax\)compress to \(r\)
→
\(BAx\)expand to \(d_{out}\)

Connection to SVD

The singular value decomposition writes a matrix as \(U\Sigma V^\top\). Keeping only the largest \(r\) singular directions gives the best rank-\(r\) approximation under common matrix norms. LoRA does not repeatedly compute the SVD of the desired update. It directly learns two factors whose product is rank at most \(r\).

03 · LoRA internals

Forward pass, scaling, and initialization

The frozen path and the trainable adapter path run in parallel. For a column-vector convention, the result is:

LoRA forward equation\[h = W_0x + \frac{\alpha}{r}BAx\]

Here \(W_0\) is frozen, \(A\) and \(B\) are trainable, \(r\) is the rank, and \(\alpha\) controls adapter strength. Many implementations also apply dropout on the adapter input during training.

Why multiply by \(\alpha/r\)?

If rank changes, the raw magnitude of the adapter output can also change. Scaling gives a convenient knob and makes rank experiments easier to control. The effective multiplier is \(s=\alpha/r\). Some newer variants use rank-stabilized scaling such as \(\alpha/\sqrt{r}\), but the classic expression is \(\alpha/r\).

Why is one matrix initialized to zero?

A common setup initializes \(A\) randomly and \(B=0\). At step zero, \(BA=0\), so the adapted model behaves exactly like the original model. Yet learning can begin:

Early gradient behavior\[\frac{\partial \mathcal L}{\partial B}=\frac{\alpha}{r}\left(\frac{\partial \mathcal L}{\partial h}\right)(Ax)^\top\]\[\frac{\partial \mathcal L}{\partial A}=\frac{\alpha}{r}B^\top\left(\frac{\partial \mathcal L}{\partial h}\right)x^\top\]

At initialization \(B=0\), the first gradient for \(A\) is zero, while \(B\) receives a gradient because \(A\) is nonzero. Once \(B\) moves away from zero, \(A\) also begins receiving a useful gradient. This starts from an unchanged base model without permanently blocking training.

Where adapters are inserted

In a transformer, LoRA is commonly attached to attention projections such as query, key, value, and output, and sometimes to feed-forward projections. The best target modules depend on model architecture, task, memory budget, and framework naming.

04 · Backpropagation

What remains frozen, and what receives gradients?

The base weight participates in the forward and backward computation, but it is not an optimizer target. Gradients are used to work out how \(A\) and \(B\) should move; \(W_0\) itself is left untouched.

Let \(G=\partial\mathcal L/\partial h\). Ignoring batch notation and using compatible outer products, the adapter gradients follow the chain rule:

Chain rule through the adapter\[\nabla_B\mathcal L=s\,G(Ax)^\top\]\[\nabla_A\mathcal L=s\,B^\top Gx^\top,\qquad s=\frac{\alpha}{r}\]

The input gradient still contains contributions from both paths:

Gradient flowing to the previous layer\[\nabla_x\mathcal L=W_0^\top G+sA^\top B^\top G\]

Freezing a parameter means “do not calculate and apply a parameter update for this tensor.” It does not mean “remove this tensor from the computation.” Activations must still pass through the frozen network.

05 · Merge and adapters

After training: keep separate or merge

Once trained, an adapter can remain separate from the base model, or its update can be merged:

Merging\[W_{merged}=W_0+\frac{\alpha}{r}BA\]

Keep adapters separate

Small files, easy task switching, and one shared base model. Inference must apply the adapter path.

Merge into the base

A single conventional weight matrix and no extra adapter multiplication. You lose easy hot-swapping unless you retain separate copies.

Adapters are also composable in principle, but simple arithmetic addition is not guaranteed to preserve every behavior. Different adapters can interfere because their learned directions may conflict.

06 · Quantization foundations

Before QLoRA: what quantization really does

Quantization stores many possible real values using a small set of representable codes. A 4-bit code has only \(2^4=16\) possible states, so a group of weights must share scaling information that maps codes back to approximate real values.

For simple uniform quantization, one may describe encoding and decoding as:

Simplified uniform quantization\[q=\operatorname{clip}\left(\operatorname{round}\left(\frac{w}{s}\right)+z,\ q_{min},q_{max}\right)\]\[\hat w=s(q-z)\]

The stored code \(q\) is small. The scale \(s\) and optional zero point \(z\) define how to interpret it. Since many original values map to one code, quantization introduces error \(e=w-\hat w\).

Map analogy

A high-precision weight is like an exact GPS coordinate. Quantization replaces it with the nearest square on a coarse map. The map is smaller, but several nearby positions become indistinguishable.

Why groups or blocks matter

One scale for an entire large tensor can be distorted by outliers. Block-wise quantization splits weights into smaller groups and gives each group its own scale, better matching local ranges at the cost of storing more scale metadata.

07 · QLoRA

Quantized base, trainable low-rank path

QLoRA keeps the pretrained base model frozen in a compact 4-bit representation and trains LoRA adapters in a higher compute precision. The quantized codes are storage; matrix multiplication uses dequantized values at an appropriate compute dtype.

LoRA pathtrainable adapters
Conceptual QLoRA forward pass\[h=\operatorname{Dequant}(W_q)x+\frac{\alpha}{r}BAx\]

The base codes \(W_q\) are never updated. Gradients train \(A\) and \(B\). This is why “training a 4-bit model” is slightly misleading: QLoRA is normally training adapters around a frozen 4-bit base, not performing ordinary gradient updates directly on every 4-bit code.

NormalFloat 4-bit, or NF4

Neural weights within a normalized block often resemble a bell-shaped distribution more than a uniform distribution. NF4 uses a non-uniform set of representable values designed to allocate its limited codes more appropriately for normally distributed weights. Dense code placement near common values reduces error compared with naively spacing all levels uniformly over the range.

Conceptual view, not a literal implementation formula

Imagine dividing the probability mass of a standard normal distribution into regions and representing each region with a suitable code value. The goal is to spend more of the 16 codes where normalized weights are statistically likely to occur. Actual implementations use predefined codebooks and block-wise normalization.

Double quantization

Block quantization needs scale constants. Across a very large model, those constants also consume memory. Double quantization quantizes those scale values themselves, replacing many higher-precision constants with compact codes plus a smaller amount of secondary metadata.

Two levels, conceptually\[W \approx c_1\cdot Q_1(W),\qquad c_1\approx c_2\cdot Q_2(c_1)\]

This schematic expresses the idea only: first quantize weights using per-block constants, then compress those constants with another quantization level.

Paged optimizers

Memory spikes can occur when long sequences or large batches create unusually large activation demands. Paged optimizer approaches rely on managed memory behavior to move optimizer pages between GPU and host memory when necessary, reducing catastrophic spikes. They are a safety mechanism, not magic free bandwidth: heavy paging can slow training.

08 · Memory accounting

Where the savings actually come from

For \(N\) base parameters, raw 4-bit storage is ideally \(N/2\) bytes, before block scales and other metadata. A 7-billion-parameter base therefore has an idealized raw code size of about \(3.5\) GB in decimal units. Real memory is higher because of metadata, modules held in other dtypes, temporary dequantization buffers, CUDA context, adapters, optimizer states, gradients, and activations.

Activations can become the next bottleneck

After shrinking model and optimizer memory, activations may dominate, especially with long context lengths. Activation memory generally rises with batch size, number of tokens, hidden width, layers, and stored intermediate tensors. Gradient checkpointing trades extra recomputation for lower activation memory.

Do not estimate only from model size

Two runs using the same model can differ dramatically because sequence length, padding strategy, micro-batch size, attention implementation, checkpointing, and optimizer configuration differ.

09 · Practical knobs

Rank, alpha, dropout, and targets

KnobWhat it controlsIf too smallIf too large
Rank \(r\)Adapter capacityUnderfittingMore memory and overfitting risk
Alpha \(\alpha\)Update scaleWeak adaptationUnstable or overpowering update
DropoutAdapter regularizationLess regularizationCan suppress useful signal
Target modulesWhere capacity is placedInsufficient coverageMore trainable parameters

Rank is not a universal quality dial. A narrow task may need little capacity, whereas broad instruction tuning or domain adaptation may benefit from more rank or more target modules. Validation quality should choose the configuration, not rank alone.

A disciplined tuning order

  1. Build a clean, representative train/validation split.
  2. Start with attention targets and a modest rank.
  3. Verify formatting, loss behavior, generation quality, and overfitting.
  4. If clearly under-capacity, increase rank or target more projections.
  5. Then tune learning rate, epochs, effective batch size, dropout, and sequence length.
10 · Implementation

A compact QLoRA training skeleton

The following example shows the architecture of a common workflow with the Hugging Face ecosystem. Package APIs can evolve, so treat names and versions as implementation-specific and check the documentation for your installed environment.

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

model_id = "your-base-model"

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=bnb_config,
    device_map="auto",
)

model = prepare_model_for_kbit_training(model)

lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()

# Next: tokenize a properly formatted dataset, configure a trainer,
# train, evaluate on held-out examples, and save the adapter.

The tiny linear-algebra core

import math
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base, rank=8, alpha=16):
        super().__init__()
        self.base = base
        self.base.weight.requires_grad_(False)
        if self.base.bias is not None:
            self.base.bias.requires_grad_(False)

        self.A = nn.Parameter(torch.empty(rank, base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, rank))
        nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))
        self.scale = alpha / rank

    def forward(self, x):
        frozen_path = self.base(x)
        adapter_path = (x @ self.A.T) @ self.B.T
        return frozen_path + self.scale * adapter_path

Production checklist

Confirm target-module names, tokenizer padding and chat template, label masking, compute dtype support, maximum sequence length, gradient checkpointing, evaluation generation settings, checkpoint strategy, and whether your final deployment expects merged or separate adapter weights.

QLoRA is not automatically better than LoRA. It maximizes memory efficiency but adds quantization complexity and can be slower in some environments because weights must be dequantized for computation. If sufficient memory exists, a higher-precision frozen base with LoRA may be operationally simpler.

12 · Failure modes

What LoRA and QLoRA do not solve

Bad data

Adapters efficiently learn noise, contradictions, and formatting mistakes too.

Missing knowledge

Fine-tuning is not a guaranteed factual database update mechanism. Retrieval may be more suitable.

Catastrophic behavior shift

A narrow or aggressive dataset can damage general usefulness even while the base is frozen, because the adapter changes outputs.

Evaluation leakage

A low loss means little if validation examples overlap training data or fail to represent deployment.

Common misconceptions

“LoRA compresses the original model.”

No. LoRA compresses the trainable update representation. QLoRA separately quantizes the frozen base model.

“Rank 64 is always better than rank 8.”

No. More rank means more capacity and cost. Whether it helps depends on task complexity, dataset size, targets, optimization, and overfitting.

“A frozen model uses no backward memory.”

Not quite. Frozen parameters do not need their own gradients or optimizer states, but backpropagation still needs relevant activations and gradients through the network to train adapters.

“4-bit multiplication happens directly for every operation.”

Usually quantized weights are compact storage and are dequantized in blocks into a supported compute precision for matrix operations. Exact kernels differ by hardware and library.

13 · Final mental model

One picture to remember

LoRA

Freeze the giant map. Learn a small set of correction directions through \(A\) and \(B\). Apply the correction beside the original path.

\[h=W_0x+\frac{\alpha}{r}BAx\]

QLoRA

Fold the giant map into a compact 4-bit form. Unfold only the pieces needed for computation, while still training the same small correction path.

\[h=\operatorname{Dequant}(W_q)x+\frac{\alpha}{r}BAx\]

The breakthrough is not merely “fewer parameters.” It is the separation of responsibilities: the frozen base carries broad pretrained knowledge, the low-rank adapter carries task-specific change, and quantization reduces the cost of keeping the base in memory.
